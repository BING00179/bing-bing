# 가상 계좌 — 설계 (2026-10-08)

사장님이 2026-09-14 와 10-08 에 정하신 것 위에 씁니다. 자동매매 1단계입니다.
**돈은 0원입니다.** 프로그램이 규칙대로 무엇을 언제 얼마나 사고 팔았을지,
그리고 **왜 안 샀는지**를 매일 기록해 웹페이지에서 눈으로 보게 합니다.
2단계(한국투자증권 실계좌)는 이 기록이 석 달 쌓인 뒤에 붙입니다.

## 1. 정해진 것 (사장님)

| | 값 | 정한 날 |
|---|---|---|
| 관찰 방식 | 우리 장부에서 가상 매매 → 익숙해지면 **한국투자증권** 실계좌 | 09-14 |
| 화면 | 기존 웹페이지 `stocks/` 에 **「가상 계좌」 탭** | 10-08 |
| 신호 | **저평가·좋은 기업 후보** (`value-record`, 매달 10종목) | 10-08 |
| 원금 | **500만 원** | 10-08 |
| 최대 보유 종목 수 | **6** (추천값 수용) | 10-08 |
| 일일 손실 한도 | **-3%** (15만 원) 넘으면 그날 매수 중지, 매도만 (추천값 수용) | 10-08 |
| 종목 비중 | 10~15% → **종목당 배정 75만 원**(15%) | §5 |
| 분할 매수 | **30 · 30 · 40** = 22.5만 / 22.5만 / 30만 | §5 |
| 분할 매도 | **+10% 에 30% / +20% 에 40% / +35% 에 30%** (장부 v1 과 같음) | §12 |
| 무효선 | 평균 매수가 대비 **-20%** → 전량 정리 | §5·§12 |

6종목 × 75만 = 450만. **현금 50만 원은 늘 남깁니다** (§5 ② "현금과 선택권을 남긴다").

## 2. 규칙 — 숫자를 보기 전에 적어 둔 것

아래는 사장님 원칙(§5)의 빈칸을 제가 채운 것입니다. **[가정]** 표시는
제가 정한 값입니다. 석 달 기록이 쌓이기 전에는 바꾸지 않고, 바꾸면
`VIRTUAL_VERSION` 을 올려 앞뒤를 가릅니다 (§7·§12 와 같은 규칙).

### 2-1. 시간 — 미래를 보지 않는다 (§8)

- 판단은 **D일 종가**로, 체결은 **D+1일 시가**로. 장부(`livetest`)와 같습니다.
- 그래서 매일 실행은 두 부분입니다: ① 어제 낸 주문을 오늘 시가로 체결 ② 오늘 종가로 내일 주문을 냄.
- 실행은 **16:00 KST 이후**에만 합니다. 15:20~15:59 에는 오늘 봉이 아직 바뀔 수 있습니다.
- 같은 날 두 번 돌아도 결과가 같아야 합니다 (날짜로 중복을 막음).

### 2-2. 들어가기

- 후보 = 그 달 `value-record` 가 적은 `setup="value"` 줄 (장부 `livetest.csv`). 순서는 `score`(저평가점수) 오름차순.
- 빈자리(6 - 보유 종목 수)만큼 위에서부터 **1차 매수 주문**. 이미 보유한 종목은 건너뜁니다.
- 1차 30% = 22.5만 원 ÷ D+1 시가 → **내림한 주 수**. 0주면 **"살 수 없음 — 1주 가격이 1차 금액을 넘음"** 으로 기록하고 그 종목은 넘깁니다. 실계좌에서도 똑같이 생길 일이라 숨기지 않습니다.
- 2차 30% **[가정]**: 1차 체결 뒤, 종가가 **1차 매수가 +5% 이상**으로 마감한 첫날 → 다음날 시가에 22.5만 원어치. ("관찰 구간 상단에서 근거를 다시 확인한 뒤" — 상단을 +5% 로 둡니다.)
- 3차 40% **[가정]**: 2차 체결 뒤, 종가가 **1차 매수가 -10% 이하**로 마감한 첫날 → 다음날 시가에 30만 원어치. 단 무효선(-20%) 미도달일 때만. ("하단까지 조정되고 근거가 유지될 때" — 하단을 -10% 로 둡니다. 2차 없이 3차는 없습니다.)
- "근거 유지" = 가장 최근 월말 판정이 여전히 "후보". 공시 위험(유상증자·감사의견 등)은 **아직 자동으로 못 봅니다** — 미구현으로 적습니다 (§4 "공시 위험" 축이 비어 있다는 §14 기록과 같음).

### 2-3. 나오기

- 기준가 = **평균 매수가**(체결 금액 합 ÷ 주 수).
- 종가가 평단 +10% 이상 마감 → 다음날 시가에 **보유 주 수의 30%** 매도(내림, 최소 1주). +20% → 40%. +35% → 나머지 전부. 각 단계는 한 번만.
- 종가가 평단 **-20% 이하** 마감 → 다음날 시가에 **전량** 매도. 사유 "무효선".
- 월말 재판정에서 "후보"가 아니게 되면 → 다음날 시가에 전량 매도. 사유 "근거 사라짐" (§5 ④ "원금을 회수했더라도 성장 근거가 사라지면 정리").
- 보유 기간 상한은 **두지 않습니다** (§5 에 없음).

### 2-4. 관문 — 주문은 셋을 다 통과해야 나간다

강의에서 가져온 구조입니다. 막히면 **막힌 이유를 기록**합니다. 이것이 "왜 안 샀는지" 입니다.

    ① 조건     위 2-2 / 2-3 의 신호가 있는가
    ② 포트폴리오 보유 종목 수 < 6 · 종목 배정 75만 원 안 · 현금 50만 원은 남는가
    ③ 리스크    일일 손실 한도: 어제 평가액 대비 오늘 평가액이 -3% 넘게 빠졌으면
               **내일 매수 주문 전부 보류**(매도는 그대로)
               무효선 도달 종목은 ①에서 이미 매도 주문

### 2-5. 비용

§6 의 실제 명세 값을 그대로 씁니다. 확인된 것과 가정을 가릅니다.

    매수 수수료 0.0137% · 매도 수수료 0.0140% · 세금 0.1998%   ← 확인됨
    슬리피지 편도 0.15%                                       ← 가정

체결가는 시가 × (1 ± 0.15%) 로 잡고, 기록에 "슬리피지 가정" 을 남깁니다.

### 2-6. 바꾸지 않는 것

`VIRTUAL_VERSION = "1"`. 위 숫자를 하나라도 바꾸면 판을 올리고 그날부터 시계가 다시 갑니다. 기록은 지우지 않습니다 (§12 의 일곱 규칙을 그대로 코드로 지킵니다 — 줄어드는 저장 거부, 정정은 새 줄).

## 3. 저장하는 것 — `trading-system/data/`

전부 CSV, `utf-8-sig`, 추가만 하고 지우지 않습니다. 셋 다 저장소에 커밋합니다.

| 파일 | 한 줄 = | 주요 칸 |
|---|---|---|
| `virtual_trades.csv` | 체결 한 건 | row_id, version, date, code, name, side(매수/매도), tranche(1차/2차/3차/매도1/매도2/매도3/무효/근거), shares, price, fee, tax, slippage, amount, reason |
| `virtual_log.csv` | 결정 한 건 (낸 것도, 막힌 것도) | date, code, name, action(주문/보류/건너뜀/체결), gate(조건/포트폴리오/리스크/체결), detail(사람이 읽는 이유 한 줄) |
| `virtual_daily.csv` | 하루 스냅샷 | date, cash, positions_value, equity, day_pnl, day_pnl_pct, halted(일일한도 발동 여부), n_positions, kosdaq_close |

보유 현황은 따로 저장하지 않고 `virtual_trades.csv` 에서 매번 다시 계산합니다 (저장이 둘이면 어긋납니다).

웹페이지용 `stocks/virtual.json` 은 위 셋에서 만든 **파생물**입니다. 지워도 다시 만들어집니다.

## 4. 매일 흐름 — `python -m src.cli virtual-update --web`

    0. 16:00 KST 전이면 "아직 마감 전" 찍고 끝 (오늘 날짜 기준, 중복 실행 안전)
    1. 장부(livetest.csv)에서 value 후보와 월말 판정을 읽음
    2. 보유·후보 종목(≤ 16개)의 일봉을 받음 — 시세 저장고 없이도 1분 안쪽
    3. 어제 낸 주문을 오늘 시가로 체결 → virtual_trades 에 적음
    4. 오늘 종가로 평가 → virtual_daily 에 한 줄
    5. 일일 손실 한도 판정 (어제 평가액 대비)
    6. 매도 신호 → 내일 주문. 매수 신호 → 세 관문 → 내일 주문 또는 보류 기록
    7. stocks/virtual.json 갱신, index.html 다시 그림
    8. 텔레그램 한 줄: 평가액·오늘 손익·내일 주문 수·막힌 것 수 (실패해도 기록은 남김)

"내일 주문"은 `virtual_log.csv` 에 action="주문" 으로 남고, 다음 실행의 3번이 그것을 읽어 체결합니다. 별도 주문 파일은 두지 않습니다.

## 5. 화면 — `stocks/index.html` 의 「가상 계좌」 탭

지금 페이지는 탭이 없는 한 장입니다. 위에 탭 둘을 둡니다: **스캔**(지금 것 그대로) · **가상 계좌**. 탭은 `src/dashboard.py` 의 방식(버튼 + JS 로 보이기/숨기기)을 가져옵니다. 폰 폭에서도 읽히게 표는 가로 스크롤.

「가상 계좌」 탭의 순서:

1. **요약 카드** — 원금 500만 · 평가액 · 현금 · 누적 수익률 · 오늘 손익 · 보유 n/6 · 오늘 일일한도 발동 여부 · 코스닥 지수 같은 기간 수익률(비교)
2. **자산 곡선** — SVG. 원금 대비 평가액과 코스닥 지수를 같은 축에. 매수·매도 체결일에 점
3. **보유 종목 표** — 종목 · 분할 단계(1/2/3차 중 어디까지) · 주 수 · 평단 · 현재가 · 수익률 · 목표(+10/+20/+35)·무효(-20)까지 거리 · 매도 단계
4. **결정 로그** — 최근 30일. 날짜 · 종목 · 행동 · 관문 · 이유. **막힌 것도 같이** ("보류 — 리스크: 어제 -3.4% 로 일일 한도 발동")
5. **체결 내역** — 전체. 날짜 · 매수/매도 · 단계 · 주 수 · 가격 · 비용
6. **규칙 표** — 2번 절의 값과 `VIRTUAL_VERSION`. 화면만 보고도 규칙을 알 수 있게

숫자마다 기준일을 적습니다 (§1). "평가액 5,120,000원 — 2026-10-09 종가 기준".

## 6. 워크플로 변경 — `.github/workflows/stock-scan-kr.yml`

   - 월말 조건도 "15:20 이후 그날 아무 때나"로 넓힘. `value-record` 는 (날짜, 종목) 중복을 건너뛰므로 안전. `monthly-review` 는 텔레그램을 보내므로 **그 달 표시 파일** `data/monthly_review_YYYY-MM.done` 을 커밋해 두 번 안 보내게.

   - 전부 `test_workflow.py` 로 검사.

## 9. 시험 — "거짓말을 하지 않나" (§13)

가짜 일봉(`tests/helpers.make_daily`)으로:

- 신호가 D 종가인데 체결이 D 시가면 **실패해야** 함 (미래 참조 금지)
- 1차 금액으로 1주도 못 사면 "살 수 없음" 이 기록에 남고 포지션은 0
- 7번째 종목은 포트폴리오 관문에서 막히고 이유가 남음
- 어제 -3.1% 면 오늘 매수 주문 0건, 매도 주문은 그대로
- +10/+20/+35 각 한 번씩만, 내림한 주 수, 마지막은 전량
- -20% 마감 다음날 전량 매도, 사유 "무효선"
- 비용을 끄면 수익률이 달라져야 함 (배선 확인)
- 같은 날 두 번 돌리면 두 번째는 아무것도 추가하지 않음
- 줄어드는 저장은 거부
- `VIRTUAL_VERSION` 이 모든 줄에 찍힘
- 화면: 막힌 결정 한 줄이 HTML 에 들어 있음, 숫자 옆에 기준일

## 10. 미구현·가정 — 숨기지 않고 적는 것

- 공시 위험(유상증자·전환사채·최대주주 변경·감사의견) 자동 확인 **없음**. "근거 유지" 는 월말 재무 판정만 봅니다.
- 2차 +5% / 3차 -10% 는 **제 가정**입니다. 사장님의 "관찰 구간" 을 숫자로 바꾼 것이라, 석 달 뒤 같이 다시 봅니다.
- 시가 체결은 **그 가격에 다 산다고 가정**합니다. 거래대금 작은 종목은 실제로는 더 밀립니다 (§6 경고와 같음).
- 코스닥만 봅니다. 코스피 943종목은 §14 ③ 그대로 아직입니다.
- 월말 후보가 0건이면 가상 계좌는 현금만 들고 기다립니다. 그것도 기록입니다.

## 11. 2단계와 이어지는 자리

한국투자증권을 붙일 때 바뀌는 것은 **4번 흐름의 3번(체결)과 6번(주문)** 뿐입니다 — `fill_orders` 가 가짜 시가 대신 실제 체결을, `주문` 이 로그 대신 REST 호출을. 규칙(`virtual_account.py`)과 기록 형식은 그대로 둡니다. 그래서 가상 석 달의 기록과 실계좌 기록을 같은 표로 비교할 수 있습니다. 실계좌 기록은 **웹에 올리지 않습니다** (§11) — 그때 `--web` 을 끄거나 가상 계좌 탭만 남깁니다.
